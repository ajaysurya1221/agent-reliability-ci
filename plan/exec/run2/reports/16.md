Deviations
- ci.yml: the brief asked for a later step that reads `$GITHUB_STEP_SUMMARY`. That cannot work: the runner gives each step its own new summary file, so a later step only sees its own empty one (the T07 report found the same). The new step therefore reads the Action's gate script from action.yml (the `id: gate` step, via PyYAML, which the Action step installs with arci). It runs that script under `bash --noprofile --norc -eo pipefail`, with fresh GITHUB_STEP_SUMMARY and GITHUB_OUTPUT temp files and an `arci` stub that prints the step's arci-report.md and exits 1. The step requires exit 1, `VERDICT: BLOCK` in the summary file, summary byte-equal to the report, and `verdict=BLOCK` in the output file. This is Astra's REVIEW 06-07 verify recipe. It checks the Action's summary write, not the summary file of the Action step itself.
- Four unit tests outside the brief's list (test_smoke_notice, test_run_yaml, test_init, test_mcp_agent) asserted `arci run` stderr exactly and had to gain the store line. test_smoke_notice's test was renamed from "prints_two_stderr_lines" to "prints_the_notice_lines". test_run_yaml now checks each path's own store line instead of yaml stderr == json stderr, since the two run directories differ.
- mcp_boundary: the stream is looked up per frame from `sys.__stdout__` (not cached, not `sys.stdout`). A cached global would trip basedpyright reportConstantRedefinition, and a lazy `sys.stdout` could be caught by the module's own `redirect_stdout(sys.stderr)` blocks. In the child, `sys.__stdout__` is the stream the import-time read used.
