# Differences from Run 6 and the earlier briefs

* Both conditions use the smallest admitted ten-round cap. Eight IDs and both arms give 16
  assignments per complete round and up to 160 per suite. All reached rounds count. The clean
  rating requires at least half the pooled final states correct for each of at least six IDs.
* The retry denominator changed from 44, then 80, required boundary deliveries to at least
  80 confirmed exposures for a complete null row. Counts retain the original boundary attempts,
  including attempts followed by an error. Incomplete delivered exchanges are listed separately.
  A missing receipt or incorrect request body invalidates the evidence.
* Both labels run the original raw-null graph. The baseline and candidate entry points identify
  their own arms for receipts. This changes descriptor identities and seeds. The first-request
  wire comparison uses the original Run 6 path. Clean opens with the same stock error and a
  successful seeded order lookup. Prompt, client options, tools, budgets and oracle follow Run 6.
* The registered endpoint is observable at tool dispatch. A malformed call rejected before dispatch
  is not visible. Exact binomial intervals are descriptive. The two arms share pair seeds, IDs
  recur, and stopping depends on outcomes.
* Whole clean/null suites run in opposite slot order across the two dates. Each suite has its
  own seeded orders. The eight order IDs recur. Gemma receives both full suites on day 1.
  Build, template, format, quantization and training may covary with model size.
* The new preflight uses five native streaming probes, observes thinking text and server load
  time, and records toy tool use without a success cutoff. It places a fresh bare 24-hex token
  only in the tool result. It does not download models, restart the server or force a cold load.
  An already-loaded slot has a measured first-probe load duration and an empty cold-load field.
* Real admission uses host-level claims, the existing Board-0 lock and process registry, a local
  pushed-branch receipt, and read-only worker snapshots. The operator supplies the final roster,
  registration and push receipt. A lock that Board-0 has yet to create cannot serialize a later
  simultaneous Board-0 launch. Matching before/after metadata cannot detect a change that
  reverts between observations.
* The in-process rehearsal uses two example slots, synthetic pins, four workers and simulated
  dates. The separate native rehearsal uses the actual launcher, serial ARCI trials, five-probe
  preflights and a disposable fake server. The eight scheduled suites use explicit rehearsal evidence.
  The `--production` extension exercises real-mode admission in a disposable checkout with
  isolated host paths and a local commit standing in for the pushed registration. Its result
  applies to the fake server and the local admission path.

* Slot family and inclusive parameter ranges come from registered `slots.json`. The Qwen
  builds share one reported quantization level. Every preflight attempt is retained under
  its registration and slot, with cold-load status and per-probe parsing failures.
* The first response is buffered through normal EOF before client parsing. Wire errors and
  parser failures have separate effects on exposure. Both standalone counters require exactly
  one receipt per reached assignment. The checker accepts sealed evidence after worker loss
  and compares a snapshot to a grade only when the oracle ran.
* Claims use atomic publication. A report gives separate totals for starts and verified rows
  and stays partial after an interruption, refusal, unreadable claim or missed same-day start.
  Process records include kernel start time. Legacy Board launcher records use command-line
  identity. The supervisor retains both acquired locks until registered groups have exited.

* A completion-write failure is latched in ARCI's sealed error as `SIZE_ZERO_RECEIPT_LOST`.
  Both counters and the checker refuse that run. Pre-header failures retain
  `no_response_headers`. A worker loss followed by grader failure retains the released
  termination and uses sealed tool events to validate delivery.
* Board group checks include re-executed ARCI workers after parent exit. When the first
  claim's date is unreadable, later rows retain their counts with unverified dates.
* Cold timing uses the first HTTP response. A missing server duration uses that response's
  wall time and sets the probe's `load_duration_missing` flag.
