# Board-0 harness

Board-0 compares the first request after a correct order or calendar lookup. The stock-sentence arm receives exactly `The lookup returned no data. Repeat the same call with the same arguments.` The empty-as-given arm receives an empty string. Both arms see the same two desk tools. The model sees the registered ask and system prompt from `tasks/tasks.json`. Temperature is 0.7, streaming and reasoning are off. The request sends neither a sampling seed nor a context override. Pin and run admission check the tag's configured 32768 context and the loaded model's digest and context.

## Preparation and live execution

Use a neutral checkout with the operator-owned environment at `$BOARD0_ENV/py`. It must contain released ARCI 2.4.1. The neutral checkout and the single host-wide claims directory must be accessible to the operator. Verify the registration and the five-slot `models.json` before preparing either day. The registry contains the Ollama version, five ordered `slots` (M1–M5), and two ordered `spares` (S1 and S2). Each row records the model tag, installed 64-hex digest, family, size and admitting `pin`. The two-slot example exercises the same allocation rule in the FIFO rehearsal.

### Amendment 1 and the corrected pins

Before pushing amendment 1, include the amended registration, models, harness and updated `board0-digests.sha256`. Keep the original descriptors and their digest list. From the study directory in the neutral checkout, use the existing host-wide claims directory. Keep the five historical outputs at `pins/board0-pin-M1.json` through `pins/board0-pin-M5.json`. The historical names have no runnable command.

1. After amendment 1 is pushed, update the neutral checkout and its local tracking ref. Put the pushed commit receipt (one line, `<40-hex-commit> refs/heads/v2/phase0`) in `/private/var/tmp/arci-board0-claims/push-receipt.txt`. Run `sh harness/run-board0.sh check`.
2. Run `sh harness/run-board0.sh real board0-pin2-M1` through `board0-pin2-M5`, once each. A completed threshold or empty-delivery failure returns nonzero and records a failed pin. An interrupted claim remains spent and blocks the roster.
3. Count failures among the five corrected pins. With at least one failure run `sh harness/run-board0.sh real board0-pin2-S1` (Qwen 2.5 7B). With at least two also run `sh harness/run-board0.sh real board0-pin2-S2` (Llama 3.2 3B). Each spare gets one attempt. Its result does not affect whether the other spare is required.
4. Run `sh harness/run-board0.sh roster` to print and save the allocation. The first failing slot receives S1 if it passes, the second receives S2 if it passes. A failed spare leaves its assigned slot vacant. Further failing slots are also vacant. Vacant rows retain their original tag, digest, pin and descriptors, and their two model-days count as undecided.
5. Run the three commands below. Prepare checks every descriptor before writing any replacement. Only a passing substitute changes the model tag in the descriptors for both days. The measured schedule derives its seeds from the compiled descriptor, so prepare also refreshes any affected entries in `scenario-collisions.json`.

```sh
sh harness/run-board0.sh prepare
sh harness/run-board0.sh descriptor-digests > descriptor-digests.sha256
sh harness/run-board0.sh digests > board0-digests.sha256
```

6. Review and push amendment 2 on `v2/phase0` with the final `models.json`, changed descriptors, collision report and both digest lists. Update the checkout, tracking ref and push receipt to that commit. Run `sh harness/run-board0.sh check`. Begin day 1 with `sh harness/run-board0.sh real board0-d1-M1-clean` if M1 is occupied, otherwise use the first occupied slot. Follow each clean run with its `-E` run. With every slot vacant there are no Board runs.

Use `list` for the canonical run names. Each of the 20 corrected probes asks the model for the token on a pebble. The native reader returns 24 random lowercase hex characters. At least 16 probes must contain the model-initiated call and a passing text answer under the registered string rule. Both additional probes must deliver the empty tool result after a scripted call and receive a completed HTTP 200 assistant response. The pin records exchanges, timing and sampled peak memory (null when unavailable). Claims are exclusive and permanent across interruption. The live lock covers metadata, pin probes, trials, grading and audit. Trial requests must belong to the active claim's frozen schedule. Day 1 runs occupied slots in ascending order, day 2 in descending order. Admission verifies the slot's recorded pin, tag and digest. Each day starts with that slot's clean suite. Local dates come from the launcher clock. A model qualifies separately each day when six distinct tasks in each family pass either clean trial. Every measured run retains all 16 tasks.

## Boundary and grade

The release exposes one MCP server per suite. The relay selects the desk from the scheduled task, unwraps its task payload and runs the released stdio bridge with an explicit two-tool allowlist. The world receives only a seed and task payload. The relay records the seed, desk and bridge source hashes, advertised tools, ordered calls, arguments and complete original responses. Each family has exactly one opening tool. The single E condition targets occurrence zero of each family's opening tool. Only one of those tools exists in any given trial. The clean row uses 16 released plain-pair descriptors without faults. The measured descriptor uses up to 26 rounds of 16 pairs, for 416 pairs and 832 trials. The released gate uses alpha 1/20, margin 1/10, stakes 1/4 and 1/2, threshold 40 in both directions, per-round seeds and four tolerated errored pairs.

The agent supplies a scripted assistant tool call and its tool message before requesting its first model response. Only the baseline replaces the blank opening. Subsequent tools execute in response order. The first assistant message with no native tool calls ends the trial. Its content is the final text. Messages with calls can carry prose, which is ignored for grading. The released boundary rejects an unknown name before charging it (src/arci/mcp_boundary.py lines 1519–1521 in this checkout, lines 1587–1589 in release 2.4.1). A known tool that returns an application error consumes a call. The limits are 12 charged calls including the opening, eight chat requests, 120 seconds for the trial and 20 seconds for grading. A final text can arrive after the twelfth charged call or on the eighth request. Empty text, exhaustion without a final message, and timeout score FAIL. A malformed backend response is an infrastructure error verified against exit 75.

The oracle takes the typed key from the seeded world. Every scalar value of the key's type that differs from the key is a decoy. The scan follows dictionary values and list elements at every depth in the snapshot, skipping dictionary keys. Boolean values are excluded for integer keys. The grader removes all occurrences of the row's order or event ID from the text. For integers it extracts tokens with `(?<![\d.,])(?:\d{1,3}(?:,\d{3})+|\d+)(?![\d]|[.,]\d)` and compares their numeric values after removing commas. For strings it scans case-sensitively from left to right, taking the longest nonoverlapping candidate at each position with a non-alphanumeric character or text edge on both sides. A trial passes when the key matches and no decoy matches.

The report shows `retrieved` for trials where a later lookup returned the target record after a blank opening. It also shows `exact`, the count whose original final text equals the canonical key after trimming outer whitespace and removing one trailing period. Only the primary grade enters the clean rating and the measured verdict.

## Evidence

On a native host, run `sh harness/tests/native-rehearsal.sh` from the study directory with port 11434 free. The rehearsal serves deterministic fake Ollama replies on loopback, pushes its copied inputs to a local bare remote, and sets `BOARD0_CLAIMS` to a fresh temporary claims directory. The production entry point `run-board0.sh` unsets this variable before starting Python. The rehearsal uses the released interpreter under `$BOARD0_ENV/py` (default environment `/Users/Shared/arci-reply0/env`), native Unix sockets and the relay's nested sandbox. It runs the five corrected pins, the last model's echo failure, S1's passing pin, and the refusal of S2. It pushes amendment 2 to its temporary local remote and runs day 1 through the substituted last slot in the registered order. A failed rehearsal prints the step and keeps its directory for inspection.

Elapsed seconds sum the complete clean and measured invocations for that slot and day, from monotonic claim creation through evidence verification and export. The audit checks tool event times and agent completion relative to the released runner deadline. Each run exports the descriptor, four ARCI files, sent-byte receipts, ledgers keyed by trial ID, audit and both counts, and the run log. Receipts join on run, task ID, seed and scheduled arm. Each exchange has the exact request bytes in base64, their SHA-256, status and exact response bytes. Count A uses the audited reconstructed conversation. Count B reads the exported receipts and sealed recordings separately. Both retain all scheduled trials through the stopping round. The independent archive verifier reconstructs both seeded worlds and grades the terminal text from response bytes. Run it from a trusted copy with the released `arci` on PATH. The SHA-256 sidecar should arrive through a trusted channel.

`check-offline.sh` uses the repository interpreter and the existing release in the shared Reply-0 environment by default. Set `BOARD0_ENV` to select another matching environment. It copies the inputs into a temporary directory, runs the released scheduler, boundary handlers, runner, oracle and gate with FIFOs, uses two artificial dates and two example slots, and verifies accepted and altered archives. The verifier's explicit `--rehearsal` mode requires two slots and offline commands. Its default mode checks five registered slots, regrades every corrected pin, reconstructs the roster and requires two measured suites per occupied slot. Both modes require all five historical files and check their run names. A complete archive with vacancies can verify successfully while K5 still falls short of ten verdicts. The rehearsal uses `BOARD0_NO_SANDBOX=1` inside the enclosing sandbox. Live servers use nested network denial unless the operator sets that switch inside an already isolated environment.


After the runs, use `sh harness/run-board0.sh report`, `sh harness/run-board0.sh assemble OUTPUT_DIRECTORY` and `sh harness/run-board0.sh pack OUTPUT.zip`. Verify the archive with the trusted `harness/check_evidence.py OUTPUT.zip OUTPUT.zip.sha256` and the released interpreter and CLI.
