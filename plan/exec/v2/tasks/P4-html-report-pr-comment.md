## Build

1. **`arci report <run> --format html [--out FILE]`** for suite runs and v1 runs: one
   self-contained file. No script, no external URL of any kind (no fonts, images, CDNs,
   links to stylesheets); inline CSS only; works offline and when attached to an email.
   Readable without colour (verdict shown as text, not only as colour), in light and dark
   colour schemes, and on a phone width. Every user-supplied string is escaped.
   Content for a suite: verdict and exit code first; one plain sentence saying what the
   verdict means; each arm's success count; the rule; wealth against the threshold per
   round as a small inline SVG chart and as a table; errored pairs against the tolerance;
   the guarantee sentence for the sealed seed mode, verbatim; fault accounting, with a
   fault that never fired flagged; the per-cell table, labelled descriptive, with the
   hidden-regression sentence; the low-baseline warning when it applies; the stored
   decision's status; prior runs; the experiment id and digests; ARCI's version. For v1
   runs: the same information the Markdown report has. Nothing the statistics documents
   forbid claiming.
   Bytes are deterministic for a given store: no timestamps, no absolute paths, stable
   ordering, floats formatted by fixed rules.
2. **PR comment from the Action**: `action.yml` gains an optional input (default off) that
   posts or updates one sticky comment on the pull request with the Markdown summary
   (verdict, per-arm success, counts, fault accounting flags, a link to the uploaded HTML
   report artifact). It finds its earlier comment by a hidden marker and edits it, never
   posting a second one. It must fail soft: without a token or outside a pull request it
   prints one line and does not fail the job; the gate's exit code still decides the job.
   Use only what the runner provides (`gh` or the REST API through a small script); pin
   any action by commit SHA as the repository already does. Document the permission it
   needs (`pull-requests: write`).
3. Tests: an HTML parser test that fails on any `<script>`, any `http:`/`https:`/`//`
   reference, any external `src`/`href`, and any unescaped injected `<` from a task id or
   failure detail; byte-determinism (render twice; shuffled input lines); golden files for
   PASS, BLOCK, INCONCLUSIVE, ERROR suite stores and one v1 store; every number in the HTML
   equal to the JSON report's; the comment script against a recorded fake API (create,
   then update, then no token) without network.
