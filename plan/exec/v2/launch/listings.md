# Listing pull requests (plan part 3b), drafts

Sent only after v2.2.0 is on PyPI. The orchestrator prepares each change on a fork under the
maintainer's account and gives a compare link; the maintainer clicks "Create pull request".
No sales wording. Do not claim that no other listed tool compares two runs: Inspect MLflow,
which is on the Inspect page, has an evaluation comparison with McNemar's test.

## 1. Inspect AI extensions page (the main one)

Repository `UKGovernmentBEIS/inspect_ai`, file `docs/extensions/extensions.yml` (read on
2026-11-14: one YAML entry per extension with `name`, `description`, `author`, `categories`;
recent pull requests by individual authors were merged with titles such as "docs: add X to the
extensions listing"; check whether `docs/extensions/extensions.json` is generated by
`docs/extensions/generate.py` or edited by hand before opening the pull request).

Entry, to be placed with the other "Analysis" entries:

```yaml
- name: "[ARCI verdict](https://github.com/ajaysurya1221/agent-reliability-ci/blob/main/docs/recipes/verdict.md)"
  description: |
    Regression verdict from two Inspect logs: reads a baseline and a candidate JSON log (epochs as rounds) and returns PASS, BLOCK or INCONCLUSIVE from a rule file written before the runs, with a stated error bound under stated assumptions.
  author: "[Ajay Surya Senthilrajan](https://github.com/ajaysurya1221)"
  categories: ["Analysis"]
```

Pull request title: `docs: add ARCI verdict to the extensions listing`.
Body (three sentences): what it reads (`inspect log dump FILE.eval > FILE.json`, one log per
arm), what it returns and the exit codes, and that it runs nothing and adds no dependency to
Inspect. Link the recipe and the statistical contract.

Before sending: run the recipe's Inspect commands against logs produced by the current
inspect-ai release, not only the 0.3.289 fixtures.
