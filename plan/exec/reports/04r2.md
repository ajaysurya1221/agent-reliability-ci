REPORT 04r2 — Status DONE

Changes
- src/arci/init.py: `_create_exclusive` and every copy-into-destination path removed (D-10). Without
  `--force` the only publication is `os.link(staged, dest)`: FileExistsError -> "output <path> exists;
  use --force to replace it"; any other OSError -> "output <path>: cannot publish atomically here (hard
  links unsupported); choose another directory or pass --force"; staging removed on every path (finally).
  `--force` keeps `os.replace`. 2b: the staged file is flushed, `fchmod`ed to the ordinary mode and
  `fsync`ed on its fd before verify/link/replace; after publication `_fsync_directory` fsyncs the parent
  (open O_RDONLY + fsync, OSError ignored). Module and `publish` docstrings now say "published
  atomically", true again.
- src/arci/runner.py: `_pythonpath` docstring only: precedence sentence qualified with the
  namespace-package exception (amended ADR 0006). No behaviour change.
- tests/unit/init/test_publish.py: exclusive-create success test and the fallback fsync test removed.
  New: no links -> exit 3 + the new line, nothing in the directory; no links + competitor created after
  the re-check -> exit 3 + new line, competitor bytes survive, no staged file; `--force` with no links
  still publishes by rename. Real-link race test kept. 2b tests: fsync order is [file, dir] and the mode
  stays ordinary; a failing staged fsync -> exit 3 "cannot write: Input/output error", directory empty;
  a failing directory fsync is ignored (exit 0, valid descriptor).
- Add-ons (all done), src/arci/descriptor.py + tests/unit/descriptor/test_round3.py (new):
  - lone surrogates U+D800-U+DFFF in any scalar or key rejected at their path
    ("lone surrogate U+D800 is not valid text; ..."); the rendered line stays UTF-8-encodable.
  - explicit `!!int` must fullmatch `INT_PATTERN` (the implicit resolver's, now a shared constant);
    explicit `!!float` must fullmatch `FLOAT_PATTERN` or a decimal integer (`!!float 2` -> 2.0). No
    underscores, no padding, no `0X`. `!!float inf` keeps its existing "not a finite number" message.
  - explicit `!!null` accepts only "", `null`, `~` (`!!null hello`/`!!null "hello"`/`!!null NULL` ->
    "invalid null ..."). Explicitness is recorded by a `DescriptorLoader.compose_scalar_node` override;
    implicit YAML 1.1 `Null`/`NULL` still resolve to null (unchanged).
  - `MAX_ALIAS_NODES = 100_000`: each re-use of an already-walked node adds its expanded size (cached
    per node) to a counter; passing the cap raises "aliases expand to more than 100000 values; write
    less reuse" at the use's path. `_check_node` state is now a `_Walk` dataclass. Large documents
    without aliases are not capped.

Deviations
- `!!float` also accepts a plain decimal integer (`!!float 2`): it has no underscores or padding, and
  rejecting it would refuse an ordinary explicit float; every other non-implicit form is refused.
- `!!float inf` / `nan` spellings return the non-finite value so the existing test's "not a finite
  number" message stands; they are still rejected.
- The old fsync test was repointed at 2b (staged fsync failure) rather than only deleted (dispatch allowed).

Open issues
- `os.fchmod` is POSIX-only (Windows lacks it before 3.13); the project already relies on POSIX
  (killpg, link semantics).
- Directory fsync is best effort by design; on macOS fsync is not F_FULLFSYNC.
