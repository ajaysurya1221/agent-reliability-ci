## Changes
- `src/arci/descriptor.py`
  1. YAML layer (`parse_yaml` → `_check_node`, run on the composed node graph before anything is
     constructed): only `str/int/float/bool/null` scalars, `!!map` mappings and `!!seq` lists are
     accepted. `!!set`, `!!omap`, `!!pairs`, `!!binary`, `!!timestamp`, `!!python/*` and custom
     tags are refused as `<path>: not a JSON value: YAML tag !!set is not allowed; ...`. The same
     walk also refuses: non-finite floats (`.nan`, `.inf`, `-.inf`, `!!float inf`) anywhere;
     malformed explicit scalars (`!!bool "WHAT"`, `!!bool yes`, `!!float "abc"`, `!!int 1.5`);
     non-string keys (`task: {1: a}`); an alias that contains itself; nesting deeper than
     `MAX_DEPTH = 100`. The duplicate-key check moved into this walk (messages unchanged). Own
     constructors for int/float/bool raise `ConstructorError`, never a bare `KeyError`/`ValueError`.
     A composer `RecursionError` becomes a DescriptorError.
  2. Every refusal is a `DescriptorError` with `file:path`. `to_manifest` also turns any
     non-pydantic `ValueError`/`TypeError` from `Manifest.create` (e.g. `hash_record`) into
     `descriptor <file>: cannot seal the manifest: ...` (defence in depth; the YAML layer already
     guarantees JSON).
  3. `source_path` (now public) maps pydantic locs structurally: the arm-union tag is skipped only
     at the position right after `baseline`/`candidate`; JsonValue `dict`/`list` tags only below
     `task` and a fault's `params`, and only where the data node is that container. A user key
     named `dict`, `list`, `module:function` or `arm mapping` is always treated as a key.
  4. Shorthand rules (oracle/contract, id/condition_id, fault/faults, occurrence/at_occurrence,
     plus the existing missing/null one-of rules) are single functions over the given keys, used by
     the models' after-validators AND by `shorthand_problems(data)`, a structural pass over the raw
     input. `loads_descriptor` merges those problems with all pydantic errors and reports
     `first_problem` (first by sorted source path).
  5. Validation is `Descriptor.model_validate_json(json.dumps(data), strict=True)`: strict at
     every level including the frozen nested models (`budgets`, `command.infra_exit_codes`,
     `decisions`, ...): `true` and `"7"` never become numbers; `6.0` is not an integer; an integer
     is still accepted for a float. Lists→tuples and strings→enums keep working because this is
     pydantic's JSON mode. Type errors read `Input should be a valid integer, got true`; a
     non-mapping arm reads `must be a mapping` (no class name).
  6. Own float resolver `FLOAT_PATTERN`: YAML 1.1 decimal floats minus the base-60 branch and
     minus underscores (`1:30.5`, `1_000.5` stay strings; `1.5`, `-0.25`, `2.`, `.5`, `1.0e+3`
     are floats; `1e3`, `1.0e3`, `-.5` stay strings, as in YAML 1.1).
- `docs/DESCRIPTOR.md` (199 lines): exact float rule; the JSON-only rule list; strict numbers; the
  reported error is "the first by **sorted** source path, not file order" (YAML-level problems are
  reported where they first occur); library calls raise only `DescriptorError`.
- `docs/schema/arci.schema.json`: unchanged — `arci schema` output is byte-identical (no model
  field, description or docstring that feeds the schema changed).
- Tests: new `tests/unit/descriptor/test_strict_input.py` (all seven items: `argv: !!set` rejected;
  three subprocesses with `PYTHONHASHSEED=1,2,3` produce one identical `record_sha256`/argv/
  prior_runs line; every tag; non-finite in task/alpha/params; constructor errors with path;
  non-string keys; recursive alias; depth; seal-failure wrapping; CLI exit 3 with file:path;
  tag-named keys under `baseline` and `task` (YAML path and python-mode pydantic mapping);
  alias conflict + unknown key/field error in both file orders at top, condition, fault and
  faults[j] level; strict numbers at top and nested; YAML floats still work; float rule).
  `test_descriptor.py`: one expectation updated (`!!int "zz"` now reports `arci.yaml:a: invalid

## Deviations (with reason)
- Item 4 mechanism: alias conflicts are not collected in a pydantic `mode="before"` validator but
  by `shorthand_problems`, a structural pass over the same raw input whose results are merged with
  the field errors before the sorted pick. Reason: any before/wrap validator makes pydantic
  re-validate everything beneath it in Python mode; under item 5's strict mode that rejects every
  YAML list for a tuple field and every string for an enum (verified: a no-op before validator on
  the parent turned valid input into `tuple_type` errors). The required outcome holds and is
  tested in both file orders at all four alias sites. The after-validators use the same rule
  functions, so direct `Descriptor.model_validate` callers get the same messages.
- Float rule also drops underscores (`1_000.5` is a string) to match the integer rule (`1_000`
  already a string). Strictly narrower than before; `arci init` never writes underscores.
- New limits beyond the brief, each to keep the "only DescriptorError" contract: non-string keys
  are rejected (`json.dumps` would otherwise turn `1:` into `"1"` silently); nesting deeper than
  100 levels is rejected with a path (pydantic's strict JSON parser stops at 200 with an opaque
  message); self-containing aliases are rejected.
- `n_per_arm: 6.0` (a float for an integer key) is now an error — part of strict numbers.

## Open issues
- Problems found by the YAML layer (syntax, repeated key, tag, malformed or non-finite scalar,
  non-string key) stop parsing, so they are reported in file order, ahead of any validation error;
  documented in DESCRIPTOR.md.
- `confidence_max: true` inside `params` is JSON and passes this layer; the frozen `Manifest`
  validator rejects it (`confidence_max must be a finite number in [0, 1]`), reported without a
  source path, as all Manifest-level errors are (unchanged from T03).
