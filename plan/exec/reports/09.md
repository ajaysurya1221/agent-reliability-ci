## Deviations
- Verdict at N=8 is BLOCK (exit 1), not INCONCLUSIVE: with `tool_error_once` on `fetch` at occurrence 0 and a `fragile` client that gives up on the first error (both as specified), every candidate trial fails, a total collapse, which N=8 decides. The doc and README say so and explain that the stderr notice's "expect INCONCLUSIVE" is generic. Getting exit 2 would need a candidate that sometimes survives (a different occurrence or a non-"give up" variant), which the brief fixed otherwise. PLAN.md's older "N=3, exit 2" acceptance was superseded by the dispatch's `n_per_arm 8`.
- `agent.py` is ~75 code lines (~107 with docstring) after ruff format, above the brief's ~60.
- The manual preflight also sends `notifications/initialized` (three requests plus the notification), so it is a well-formed MCP session; the bridge ignores the notification.
- The preflight launches the server described by `mcp.inspector.json` with `sys.executable` in place of its `"python"`, so the doc and the Inspector config cannot drift apart; the test asserts the config's `env` is `{"PYTHONPATH": "."}`.
- The doc's setup suggests `python -m venv .venv && . .venv/bin/activate && pip install agent-reliability-ci` because the committed `python` must have arci importable (the bridge); a `uv tool install` interpreter is isolated. Before PyPI, the clone's environment is used instead (stated).
