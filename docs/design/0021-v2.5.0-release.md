# 0021: v2.5.0, a command for testing a change and five evaluation-tool routes

Record by the orchestrator, 2026-11-28. The maintainer asked for this release on 2026-11-28,
after pull requests 44 and 45 were merged to `main` (`a16c20a`). An independent consultant
(Codex, read-only) reviewed `fac58f6..a16c20a` before the release was cut. It found no changed
meaning for any existing command or record, and three problems against pinned text; their
disposition is below.

## Why

`main` holds two new commands since the tag `v2.4.1`, so this is a minor release under
[COMPATIBILITY.md](../COMPATIBILITY.md): a valid existing documented command and supported
record keep their meaning. Both commands were built on the maintainer's decision before any
outside request (decisions D-40 and D-41 in the project's plan records); nobody outside the
project has asked for them or used them.

## What ships

- **`arci check-change`** ([record 0019](0019-check-change.md),
  [recipe](../recipes/check-change.md)): one unscored discovery launch, then the rule, its
  digest and the launch order are written before either evaluated command runs; paired rounds
  in that order; the released verdict rule after each complete round; a stop at the first
  decision. Exit 0 PASS (or a finished `--plan-only`, which gives no verdict), 1 BLOCK,
  2 INCONCLUSIVE, 3 ERROR, 128 plus the signal when cancelled.
- **`arci convert --from promptfoo`** and **`check-change --format promptfoo`**
  ([record 0020](0020-eval-tools.md), [recipes](../recipes/eval-tools.md)): promptfoo results
  JSON (version 3) is converted to neutral JSONL rows that carry the source digest and the
  reader's name; sealed decisions name the converted snapshot as `jsonl`. Recipes for
  DeepEval and Opik (pytest JUnit), MLflow and Langfuse (two example exporters in
  `examples/integrations/`, not in the wheel).
- One fix made while preparing this release, with a test that failed before it: `convert`
  names a temporary file it could not remove on a refusal too, not only on success.
  `check-change`'s code is exactly what pull request 44 and 45 put on `main`: a change to its
  signal handling was written and reviewed twice during preparation, each review found a new
  defect in it (the last one: the command could no longer be stopped while the terminal was
  stalled), and it was taken out rather than shipped untested in the field.
- Not code: log readers checked against newer client versions; the descriptive log-signals
  study (`docs/results/log-signals-study/`); uv 0.13.4 in the workflows; version pins.

## What can differ from 2.4.1

No existing command, exit code, fixed text or record changes meaning. Records that carry the
ARCI version (for example the decisions `arci logs` writes) now carry 2.5.0, so their seal
differs from a 2.4.1 run on the same input, as at every release. `verdict` and `verdict-rule`
keep their path, parser and rule
checks; the consultant compared discovery for JUnit, CSV, JSONL and Inspect between the two
revisions and reproduced the order-desk CSV decision byte for byte. `check-change`'s
`plan.json` is new; for `--format promptfoo` it also holds `reader`, `scored_format` and
`tool_version`. The frozen list of four input formats a sealed decision may name is unchanged.

## Known gaps against pinned text, not closed by this release

1. Record 0019, lines 110 to 111: "Memory use does not grow with the number of rounds." The
   campaign keeps every capture's path and digest and the outcomes of every round, and each
   assessment rebuilds the prefix, so memory grows with rounds times tasks (a few values per
   task per round; one results file is read at a time). `--max-rounds` is capped at 100,000.
   The sentence is false as written; it is neither weakened nor reinterpreted here.
2. Record 0020, acceptance item 4: "each refusal ... leaves no new file". When the operating
   system refuses three times to remove the temporary file `convert` created next to `OUT`,
   that file stays. `convert` now names it on success and on refusal.
3. Record 0019, lines 114 to 116: when interrupted, the command "writes that the campaign was
   cancelled (no verdict) and ends with the conventional status for that signal". It does, also
   when the signal arrives while a finished verdict is being printed; the verdict lines already
   printed then stay above the cancellation line in the terminal and in `verdict.txt`, and the
   exit status is 128 plus the signal. The exit status and the last line that starts with
   `ERROR:` or `VERDICT:` are the result. A failure writing to the terminal while the verdict
   is printed can likewise add an ERROR report below it, with exit 3.
4. Both gaps listed in [record 0018](0018-v2.4.1-release.md) stay open: the timing dependence
   of the graded final state for scripted MCP clients, and the dropped `--keep` write without
   F24 when only the locked re-read finds the table unreadable.

leaves the group and is not stopped (record 0019).

## Order of publication

The skills and the plugin on `main` name `realornoise==2.5.0` from the merge until both publish
jobs finish, so a run of the skill in that window fails at install. The README names 2.5.0
from the merge as well: its Action pin works once the tag exists (the Action installs from the
tag's source), `agent-reliability-ci==2.5.0` once the main publish job has finished, and
`realornoise==2.5.0` once the second one has. The tag is pushed on the
merge commit only after hosted CI on it is green. The main package is published before
`realornoise`. A plugin directory or an installed plugin copy may keep an earlier version; no
claim is made about when either updates.

## What the release may and must not say

May say: two new commands; a converted promptfoo file gives a descriptive verdict and fresh
paired runs give the error bound under the assumptions `check-change` prints; the routes and
the versions each was tested with (promptfoo 0.125.1 and 0.126.0, DeepEval 4.3.6, Opik 2.3.7,
MLflow 3.18.0 with a local store, Langfuse Python SDK 5.2.0 with tracing off and no server).

reports pass-rate ranges with `--repeat`); that anything was shown about real agents, hosted
models or live servers; that ARCI detects caches in general; that anyone outside the project
uses these routes; "first" or "only". Otherwise as in records 0013, 0014 and 0018.
