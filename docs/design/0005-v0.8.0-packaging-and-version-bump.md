# 0005: v0.8.0 packaging metadata and the version bump (v0.8.0)

Decision by the orchestrator (Claude Fable 5.1), reviewed by the read-only consultant (gpt-6-astra,
xhigh) and an independent Opus 5.5 reviewer, 2026-10-13. Part of the v0.8.0 onboarding sprint
(plan/exec/PLAN.md, task 12). This record exists because `pyproject.toml` and `uv.lock` are frozen
(`FROZEN.sha256`), and the repository's rule is that a frozen file changes only with a design record
and an explicit re-freeze commit that says why.

## Problem

v0.8.0 is the first release published to PyPI. The frozen `pyproject.toml` still says `0.7.0`, has no
project URLs, classifiers or keywords, and builds an sdist from every non-ignored file in the tree
(about 20 MB, mostly archived evidence under `docs/`). The lockfile records the project version too.
PyPI versions are immutable, so the wheel must carry the right version before anything is published.

## Decision

One commit changes exactly these things in the two frozen files, and nothing else:

- `pyproject.toml`: `version = "0.8.0"`; `[project.urls]` (Homepage, Source, Changelog, Issues,
  Design records); `classifiers` (development status, intended audience, Python versions, topic,
  OS :: POSIX; no `License ::` classifier because the SPDX `license` field already applies);
  `keywords` copied from `CITATION.cff`; `[tool.hatch.build.targets.sdist] only-include = ["src/arci",
  "README.md", "LICENSE", "NOTICE", "CHANGELOG.md", "pyproject.toml"]`. Dependencies, the build
  backend, the console script, the wheel target and every tool section are untouched.
- `uv.lock`: regenerated with `uv lock` so the root package records `0.8.0`; no dependency changes
  (`uv lock --check` passes).
- `FROZEN.sha256`: the two hashes above are replaced, and the design records written during this
  sprint (0005 to 0009) are added so that `docs/design/**` is pinned in full, as `AGENTS.md`
  describes. Every other hash is unchanged.

In the same release: `src/arci/__init__.py` and `CITATION.cff` move to 0.8.0 in lockstep (neither is
frozen), the release workflow's guard refuses any tag that does not equal `v` + this version, and
the sdist is verified to contain only the listed paths.

## Consequences

- The wheel is unchanged in content by this record; only metadata, the version and the sdist
  contents change.
- The v0.7.0 release commit (`e304e81`) re-froze the same two files without a design record; from
  v0.8.0 on, every version bump carries one.
- The sdist no longer contains tests, examples or archived evidence. Reproduction of the evidence
  package still needs the repository at the tagged commit, as `docs/reports/ci-gate-2026-10-06`
  already states.

## Not in v0.8.0

Dynamic versioning, a `__version__` read from package metadata, hash-pinning the build backend
(hatchling stays `>=1.27,<2`), a TestPyPI leg.
